# Готовые SQL-проверки безопасности (для SQL Editor Supabase)

Это те же девять SQL-блоков, что в `docs/backend-security-checklist.md` (пункты 1, 2, 3, 4, 5, 6, 7, 8, 11), только каждый в отдельном файле, без изменений. Источник правды: чек-лист; если блок в чек-листе поменяется, эти файлы нужно сделать заново (разбор тот же, что в `supabase/tests/run.mjs`, функция `extractDocChecks`).

Как запускать каждый файл: открыть, Ctrl+A, Ctrl+C; в Supabase SQL Editor нажать New query, вставить, Run.

- `Success. No rows returned`: проверка пройдена.
- Красная ошибка со словом `ПРОВАЛ`: не пройдена, текст ошибки скопировать целиком.
- Окно «потенциально опасный запрос»: нажать Run this query (проверка сама отменяет свои изменения).

Проверки 5 и 6 требуют, чтобы админ уже был создан (HUMAN_ACTIONS.md, шаг 5). Пункты 9 и 10 чек-листа (настройки входа, Security Advisor) делаются руками в панели, SQL у них нет. Пункт 4 дополняется ручной проверкой публичной ссылки на картинку (см. чек-лист).

Не запускать в Supabase файлы из `supabase/tests/`: это заглушка для пробной базы.
