# API каталога GDS «Джедес» (Supabase, REST)

Версия 2026-10-08. Это контракт между базой и сайтом (и будущей админкой). Своего кода сервера нет: REST-интерфейс создаёт сам Supabase (PostgREST) по таблицам из `supabase/migrations`. Права и видимость строк задают `002_rls.sql` и `003_storage.sql`. Проверки безопасности: `docs/backend-security-checklist.md`; автоматические SQL-тесты: `supabase/tests`.

Статус проверки: таблицы, политики, права и ограничения проверены SQL-тестами на одноразовой PostgreSQL с заглушкой Supabase. Сами HTTP-запросы и коды ответов ниже выведены из документации PostgREST и Supabase и **на живом проекте не проверялись**.

## Подключение

| Что | Значение |
|---|---|
| Адрес (Project URL) | `https://<ref>.supabase.co` (Project Settings, раздел Data API, либо кнопка Connect) |
| Публичный ключ | `sb_publishable_…` (в ТЗ он назван «anon key»; у старых проектов ключ `anon` в формате JWT). Безопасен для кода сайта, виден всем |
| Заголовок | `apikey: <публичный ключ>` в каждом запросе |
| Вошедший пользователь | дополнительно `Authorization: Bearer <access_token>` (токен выдаёт `POST /auth/v1/token?grant_type=password`) |
| Формат | JSON, фильтры PostgREST: `?select=…&order=…&limit=…&slug=eq.altair` |
| Запрещено на сайте и в браузере | ключи `sb_secret_…` и `service_role`: они обходят все политики |

CORS: Supabase принимает запросы с любых сайтов, поэтому защита держится на политиках RLS и правах, а не на списке разрешённых адресов.

## Таблицы и поля

Ограничения проверяет сама база; сайт и админка должны проверять то же заранее, чтобы показывать понятные ошибки.

| Таблица | Колонки | Ограничения значений |
|---|---|---|
| `brands` | `id` uuid, `name`, `full_name`, `country` (обязательные), `description`, `logo_url`, `is_active` (по умолчанию true), `created_at` | текст не пустой и не из одних пробельных знаков (пробел, табуляция, перевод строки), имя и полное имя до 200 знаков, страна до 100, описание до 4000; `logo_url`: только `https://` и только знаки `A-Z a-z 0-9 . _ ~ : / ? # % & = + -`, до 2048 знаков (нет пробелов, кавычек, `< > \`, скобок, `;`, `,`, `@`, `$`, `!`, `*`, `[ ]`); не-ASCII знаки надо кодировать через `%XX` |
| `categories` | `id`, `name`, `slug` (уникальный), `created_at` | slug: латиница в нижнем регистре, цифры, одиночные дефисы между частями (`hookah-tobacco`), до 64 знаков; имя до 200 |
| `products` | `id`, `brand_id`, `category_id`, `name`, `slug` (уникальный), `line`, `tagline`, `description`, `aroma_profile`, `weight_g` numeric(6,2) по умолчанию 25, `nicotine_mg` numeric(4,2) или null, `is_active`, `created_at`, `updated_at` (ставит база при изменении строки; у ещё не менявшихся строк, в том числе у вкусов из начального сида, значение пусто, null) | slug как у категории; имя до 200; линейка до 100; подпись и нота до 200 или null; описание не пустое, до 4000; вес от 0,01 до 9999,99 (NaN отклоняется); крепость null или от 0 до 99,99 (NaN отклоняется); текстовые поля не из одних пробельных знаков; `brand_id` и `category_id` должны существовать |
| `product_images` | `id`, `product_id`, `image_url`, `sort_order` (по умолчанию 0) | `image_url` как `logo_url`; `product_id` должен существовать |
| `stores` | `id`, `name`, `address`, `city`, `latitude`, `longitude`, `phone`, `email`, `working_hours`, `is_active`, `created_at` | широта от -90 до 90, долгота от -180 до 180 (NaN и бесконечность отклоняются); телефон из цифр, пробелов, `+ ( ) -`, 5-32 знака; e-mail латиницей вида `имя@домен.зона` (в имени `A-Z a-z 0-9 . _ % + -`, зона от двух букв) до 254 знаков; часы до 500; адрес до 500; название, адрес и город не из одних пробельных знаков |
| `user_roles` | `id` (= id пользователя в Auth), `role` (только `admin`), `created_at` | запись только вручную владельцем в SQL Editor |

Удаление: бренд или категорию с вкусами удалить нельзя (код 23503): скройте их через `is_active = false`. Удаление вкуса удаляет его строки в `product_images` (файлы в Storage остаются, их удаляют отдельно). Удаление пользователя в Auth удаляет его роль.

## Матрица доступа

Для таблиц каталога «чужой пользователь» = обычный вошедший: данные общие, личных строк нет. Для `user_roles` показано, что чужую строку не видит никто, кроме владельца-сессии. «0 строк» значит: ошибки нет, но ничего не изменилось.

| Объект и действие | Аноним | Вошедший, не админ | Чужой пользователь | Админ |
|---|---|---|---|---|
| `brands`, `stores`: чтение | активные | активные | активные | все |
| `products`: чтение | активные вкусы активных брендов | то же | то же | все |
| `product_images`: чтение | картинки видимых вкусов | то же | то же | все |
| `categories`: чтение | все | все | все | все |
| 5 таблиц каталога: вставка | отказ 42501 (права) | отказ 42501 (политика) | отказ 42501 | разрешено |
| 5 таблиц каталога: изменение, удаление | отказ 42501 (права) | 0 строк | 0 строк | разрешено |
| `user_roles`: чтение | отказ 42501 | только своя строка (у обычного пользователя её нет) | не видит чужую | только свою |
| `user_roles`: вставка, изменение, удаление | отказ 42501 | отказ 42501 | отказ 42501 | отказ 42501 (роли выдаёт владелец вручную) |

| Storage: список файлов своих двух бакетов | нет | нет | нет | да |

## Файлы: соглашение об именах

Политики Storage принимают загрузку админа только с такими путями (иначе отказ):

| Бакет | Путь | Размер | Типы |
|---|---|---|---|
| `product-images` | `<slug-вкуса>/<uuid>.<расширение>`, например `altair/3f2b9c1e-0000-4000-8000-000000000001.jpg` | до 5 МиБ | `image/jpeg`, `image/png`, `image/webp`, `image/avif` |
| `brand-logos` | `gds/<uuid>.<расширение>` | до 2 МиБ | те же |

`uuid` в нижнем регистре; расширение одно из `jpg`, `jpeg`, `png`, `webp`, `avif` в нижнем регистре; slug как в таблице `products` (латиница, цифры, дефисы). SVG не разрешён намеренно. Публичная ссылка: `https://<ref>.supabase.co/storage/v1/object/public/<бакет>/<путь>`; эту ссылку (и только её, с `https://`) записывают в `image_url` или `logo_url`. Размер и типы применяет сам Storage при загрузке; в песочнице они не воспроизводятся.

## Примеры запросов для сайта

Все вкусы с брендом, категорией и картинками (то, что нужно главной странице). Работает с публичным ключом, фильтр по `is_active` ставить не нужно: политики его уже применяют.

```
GET {URL}/rest/v1/products?select=slug,name,line,tagline,description,aroma_profile,weight_g,nicotine_mg,brand:brands(name,full_name,country),category:categories(name,slug),images:product_images(image_url,sort_order)&order=created_at.asc&images.order=sort_order.asc
apikey: <публичный ключ>
```

(Параметр `images.order=…` по псевдониму встроенной таблицы это синтаксис PostgREST; на живом проекте не проверялся.)

Порядок вкусов. В таблице нет колонки порядка. Вкусы из сида записаны с `created_at`, различающимся на миллисекунду, поэтому `order=created_at.asc` даёт порядок из ТЗ (Altair, Betelgeuse, Vega, Naos, Proxima, Sirius, Alcor, Capella, Mira, Isida), а `order=name.asc` алфавитный. Новые вкусы получат более поздний `created_at` и встанут в конец; если нужен другой порядок, отдельная колонка порядка добавляется новой миграцией (решение владельца).

Точки продаж и контакты:

```
GET {URL}/rest/v1/stores?select=name,address,city,latitude,longitude,phone,email,working_hours
apikey: <публичный ключ>
```

Вкус по slug:

```
GET {URL}/rest/v1/products?slug=eq.altair&select=*,images:product_images(image_url,sort_order)
apikey: <публичный ключ>
```

## Коды ошибок Postgres, которые вернёт REST

| Код | Что значит | Когда |
|---|---|---|
| 42501 | нет права или политика RLS запретила | запись без прав админа; чтение `user_roles` без входа |
| 23514 | нарушено ограничение значения | плохой slug, ссылка не `https`, координата вне диапазона, пустой текст, вес 0 |
| 23505 | такое значение уже есть | повтор slug |
| 23503 | нарушена связь | удаление бренда или категории со вкусами; несуществующий `brand_id` |
| 23502 | обязательное поле пустое | нет `name`, `description`, `image_url` и т.п. |
| 22003 | число не помещается | вес от 10000, крепость от 100 |

Тексты ошибок PostgREST содержат имя ограничения (например, `products_slug_format`), поэтому админка может показать понятное сообщение по имени.

## Правила для сайта: значения из API недоверенные

База ограничивает значения (узкий набор символов в ссылках и e-mail, нет кавычек и `< > \`), но это страховка, а не замена защиты в самом сайте. Тексты в таблицах пишет админ, а аккаунт админа может быть украден, поэтому:

1. Любое значение из API (названия, описания, адреса, ссылки) вставляйте в страницу через `textContent` или экранирование, **не** через `innerHTML` и не склеиванием HTML-строк.
2. `image_url` и `logo_url` ставьте только в `src` через DOM-свойство (`img.src = …`), а не в строку HTML или inline-стиль. Перед выводом проверяйте на сайте, что адрес начинается с `https://<ref>.supabase.co/storage/v1/object/public/` (адрес вашего проекта).
3. Когда на сайт добавят политику CSP (заголовок или тег `meta`), в `img-src` разрешите только свой домен и `https://<ref>.supabase.co`, в `connect-src` тоже `https://<ref>.supabase.co`. Любой другой источник картинок должен быть решением владельца.
4. Привязать адреса картинок к вашему проекту можно и в самой базе (после создания проекта, когда известен `<ref>`): `alter table public.product_images add constraint product_images_url_host check (image_url like 'https://<ref>.supabase.co/storage/v1/object/public/product-images/%');` и аналогично для `logo_url` с бакетом `brand-logos`. Я этого не включаю по умолчанию, потому что при переходе на собственный домен хранилища ограничение придётся менять (решение владельца).

## Что в этом контракте сознательно не сделано

- Нет журнала действий админа (кто и когда менял каталог): в ТЗ его нет. Рекомендация и схема: `docs/adr/0001-supabase-backend.md`, раздел «Остаточные риски».
- Нет собственных лимитов частоты запросов. Каталог публичный по замыслу и читается без входа; если на сайте появятся формы или поиск, лимиты нужно будет добавлять отдельным решением.
- Нет возрастной проверки на уровне API: любой, у кого есть публичный ключ, может получить данные каталога. Возрастной экран сайта работает только в браузере. Это вопрос к юристу (HUMAN_ACTIONS.md, раздел «Вопросы юристу»).

## Правила изменения контракта

Только добавлять: новые колонки с `default` или допускающие null, новые таблицы, новые политики. Удаление и переименование колонок, смена типа, ужесточение ограничений на заполненной таблице делаются отдельным релизом и по решению владельца.

Две ловушки для будущих правок:

1. **Новая таблица в `public` сразу должна получить `enable row level security`, явные `grant` и политики.** Проекты Supabase, созданные до 30.05.2026, по умолчанию выдают ролям `anon` и `authenticated` полный набор прав на любую новую таблицу (без RLS она открыта всем); в более новых проектах права не выдаются вообще (без `grant` REST отдаёт пустые ответы). Образец: начало `001_init.sql` и `002_rls.sql`.
2. **Новая колонка в публичной таблице сразу видна всем**, у кого есть право `select` на таблицу. Служебные поля (внутренние заметки, закупочные цены и т.п.) в эти таблицы класть нельзя: заводите отдельную таблицу без прав для `anon`.
